Selectable markdown, regenerate, per-message copy and time, waiting dots

Message UX round-up:

- Waiting for the model's first token no longer renders an empty bubble:
  a streaming reply with no thinking, tools or text yet shows the chat
  TypingIndicator inside the bubble.
- Markdown text is now SELECTABLE. MujicaUI's MarkdownView builds
  unselectable elements and hides its parser in an internal package, so
  Atlas carries its own renderer adapted from the mygo-agent reference:
  mdparse.go parses the block subset (headings, prose runs that merge
  across blank lines so a drag crosses paragraphs, bullet and ordered
  lists, quotes, tables, fenced and indented code, rules) and mdview.go
  renders every element with Selectable() — prose, list items, headings,
  quotes and table cells all support drag-select and copy. Inline code,
  bold and strikethrough ride constructor spans; paragraphs containing a
  link render in element form so the link stays clickable; code fences
  use chat.CodeBlock with its built-in copy. Blocks cache on the row
  element via ui.Local and re-parse when the source changes.
- Regenerate is real: the assistant row's refresh button drops that reply
  and everything after it, appends a fresh streaming reply row (id minted
  with a regenSeq nonce so cached element state never leaks between
  replies) and restarts the agent loop over the same history. It refuses
  with a toast while a reply is in flight.
- Message actions rebuilt as two quiet icon buttons instead of the
  library toolbar (whose like/dislike/speak/share/edit Atlas never
  used): Copy on EVERY message (user messages included) writes the row
  text to the clipboard, Regenerate only on assistant replies, plus the
  message time as muted text.
- The chat/agent mode picker is gone from the composer — Atlas is an
  agent console and the mode stays Agent. The unused thread.rating field
  went with it.
